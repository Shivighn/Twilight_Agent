# 1. Daily Issue Assignment

Once every day, query the `issues` table and find issues where:

```text
assignee_id IS NULL
```

For each such issue, assign it to the appropriate Fleet Manager.

Example issue:

```json
{
  "issue_number": 367,
  "vehicle_number": "TG13T1986",
  "category_id": null,
  "summary": "Driver Complaints: Hand wash broken \nEntry door issue",
  "status": "Closed",
  "source": "Inspection",
  "reported_at": "2026-03-13 02:43:42.427+00",
  "assignee_id": null
}
```

The Fleet Managers are currently:

```text
anudeep_mukkoti
venky
```

Do not hardcode names blindly if the existing DB already contains staff/user information that can be used.

# 2. Determine Which Fleet Manager Owns the Issue

For each unassigned issue:

### Step A — Find the vehicle's trips in the last 10 days

Using the issue's:

```text
vehicle_number
```

find which trips that vehicle ran during the **previous 10 days**.

Use the existing trips/services schema and existing DB access patterns.

Determine the relevant `service_id`.

If there are multiple trips/services in the last 10 days, use the most appropriate/recent service according to the existing data model — preferably the latest relevant trip.

Do not invent a new ownership rule without checking the existing schema.

---

### Step B — Find the service in-charge

Use the existing `services incharge` table.

Example:

```json
{
  "service_id": "1123",
  "parking_incharge_id": "ram_charan",
  "fleet_manager_id": "anudeep_mukkoti"
}
```

So:

```text
service_id → fleet_manager_id
```

This `fleet_manager_id` becomes the issue's assignee.

Example:

```text
Issue 367
Vehicle: TG13T1986
Latest relevant service: 1123
Service fleet manager: anudeep_mukkoti

=> issues.assignee_id = anudeep_mukkoti
```

# 3. Assignment Rules / Edge Cases

Implement safely:

### If issue already has an assignee

Skip it.

```text
assignee_id IS NOT NULL → do nothing
```

### If no trip exists for the vehicle in the last 10 days

Do not assign randomly.

Log the issue and skip it.

### If a trip exists but no service-incharge record exists

Do not assign randomly.

Log it and skip it.

### If the service has no fleet manager

Do not assign randomly.

Log it and skip it.

### Only update the issue when a valid Fleet Manager has been determined.

Use an idempotent implementation so running the job twice does not create inconsistent assignments.
